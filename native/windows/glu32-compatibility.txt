Wine GLU helper on the native Windows backend
============================================

This is the unmodified upstream dlls/glu32 implementation, built as native
x86 and x64 PE DLLs. Wine supplies the GLU math, image scaling/mipmaps,
tessellation and quadric code. Windows supplies OpenGL/WGL and the hardware
driver. No Wine opengl32 or Unix driver is introduced.

Demise B153's x86 GraphOGL.dll imports exactly gluBuild2DMipmaps and
gluErrorString from GLU, plus native OpenGL/WGL entrypoints. This motivates
the helper; it does not establish actual gameplay compatibility.
The staged game's original files and source archive are not modified.
Its archived renderer setting is GraphSWR; the /NODIRECTX launch alone does
not prove that GraphOGL or GLU is used. An actual GraphOGL game check requires
an explicit, separately tested renderer selection.
The games-10 trial selects GraphOGL in private configuration and reaches the
evaluation reminder, but crashes during startup before that renderer is
observed. The native-GLU control also crashes. Wine GLU was loaded in the
Wine trial, but actual game GLU calls/rendering remain unverified.

Provider selection
------------------
The catalog entry is {L"glu32",{}}: there are no additional Wine dependency
modules. glu32=b selects Wine, glu32=n selects native, and glu32=b,n permits
native module fallback if the Wine DLL is unavailable. The native OpenGL
backend remains native regardless of the GLU helper choice. Existing
startup-import and runtime-loader selection handle static/dynamic clients.

NURBS is an explicit upstream gap. Wine gluNewNurbsRenderer returns NULL;
the remaining NURBS entrypoints contain unsupported assertions. Applications
needing NURBS must select native GLU. A b,n module load order DOES NOT retry
individual unsupported functions in native GLU. The fixture records this
availability difference; it does not count Wine NURBS as passing coverage.

The GLU version string is not provider evidence: Wine deliberately returns
a Microsoft-compatible version string. Tests verify mapped backing-file
identity and static import jump-thunk targets instead. Every OpenGL IAT slot
in the selected GLU module is checked against the genuine native OpenGL DLL.

Tests
-----
Build: build-glu32-probe.ps1 (MinGW32/64, static compiler runtimes).
Run: test-glu32.ps1 -RuntimeDirectory <stage> -HelperDirectory <builtin-dir>.
Use -PreCatalog for the explicit application-local standalone helper path;
that mode does not claim integrated catalog/load-order fallback coverage.
Use -CpuOnly to avoid creating any window or OpenGL context.

The fixture verifies independently expected projection and inverse values,
singular / zero homogeneous divisor errors, ASCII/Unicode error lookup,
quadric error callbacks, and tessellation of a concave polygon, a hole and
a self intersection. Tessellation checks total triangle area and callback
data/combine weights, rather than requiring an implementation-specific
triangle ordering.

GPU cases use a brief owned 64x64 window and native WGL context. They test
3x5 non-power-of-two mipmaps with padded/offset unpack data and preserved
pixel-store state, complete level dimensions and texel colors, independent
colored mipmap/scaling averages, 1D mipmap levels, invalid dimensions/formats,
projection matrix values, sphere/disk raster pixels and tessellated concave
pixels. Intel/default and NVIDIA/discrete fixtures are distinct, and actual
GL_RENDERER is recorded. No SwapBuffers, game input, host modeset, audio or
screen capture occurs. Readback is limited to the fixture's own render target.
Each process has a 30-second runner timeout; setup failures fail the suite.

there are no additional Wine dependency modules or new shim hooks.
